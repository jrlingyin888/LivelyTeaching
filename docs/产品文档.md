# 小象课堂 LivelyTeaching · 产品文档

> 版本 V0.1 · 2026-08 · 独立开发者项目

---

## 一、一句话定位

**老师在课堂上说一句话，屏幕上就出现一个能动手操作的 3D 实验。**

不是播动画，不是看视频——学生可以拖、可以点、可以改，物理是真算出来的。

---

## 二、为什么做这个

课堂上讲抽象概念时，老师手上只有三种东西：一张挂图、一段视频、一套实物教具。

| | 问题 |
|---|---|
| 挂图 / PPT | 静态，学生看不见过程 |
| 视频 | 只能看，不能动手，讲到哪停不下来 |
| 实物教具 | 贵、占地方、很多实验根本做不了（称大象、看细胞、模拟日食） |

而已有的 3D 课件产品，几乎都是**做好的固定资源包**——老师想讲的知识点如果不在库里，就没有。

**小象课堂的切入点：让课件是「生成」出来的，而不是「买」来的。**

---

## 三、目标用户

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 一线老师（首要） | 课堂讲解、公开课 | 上课前 1 分钟能拿到、投屏就能用、不出错 |
| 家长 | 在家陪孩子讲题 | 手机 / 平板打开就能玩，孩子看得懂 |
| 教研组 / 机构 | 备课资源建设 | 能积累、能复用、能分享 |

**V0.1 先服务前两类**，因为他们能立刻给出真实反馈。

## 四、产品是什么样的

### 使用流程

```
老师说：「我要讲曹冲称象」
   ↓  语音 / 文字输入
识别学科、知识点、需要的物体
   ↓
匹配到「曹冲称象」场景模板
   ↓
装配 3D 场景（水面 · 浮力 · 吃水线 · 交互逻辑）
   ↓
一个链接 → 投屏 / 触摸白板 / 手机，直接开讲
```

### 已实现的场景：曹冲称象

学生跟着五步走完整个实验：

1. **大象上船** — 船身下沉
2. **刻下吃水线** — 在船舷自动标出红线
3. **大象下船** — 船身浮起，红线留在船上
4. **装载石块** — 一块块往船上放，实时看吃水深度逼近红线
5. **得出结论** — 对齐的瞬间弹出：石头总重 = 大象体重

**浮力是真算的**，不是预设动画：

```
吃水深度 d = 载重总质量 m ÷ (水密度 ρ × 船底面积 A)
```

12 块石头的重量之和精确等于大象体重（4,400 kg），所以最后一定严丝合缝地对上 0.500 m。老师追问原理时答得出来，这是这个产品和「播动画」的根本区别。

## 五、核心设计决策

### 1. 场景模板化，不是「AI 现场生成一切」

AI 能生成**外观**（大象长什么样），生不出**交互逻辑**（浮力怎么算、吃水线怎么标）。

所以架构上分得很清楚：

| 层 | 谁来做 | 说明 |
|---|---|---|
| 外观资产 | AI 生成（即梦 → Tripo） | 大象、船、石块的 3D 模型 |
| 场景装配 | 场景模板（代码） | 水面、比例、光照、镜头 |
| 交互逻辑 | 场景模板（代码） | 浮力、拖拽、数据面板、结论判定 |
| 教学编排 | 模板参数 | 分步演示、提示文案 |

**一个模板覆盖一类知识点，换个外观资产就是另一节课。** 这是这个产品能规模化的关键。

### 2. 素材命中优先，实时生成兜底

AI 实时生成一个 3D 模型要 1.5–3 分钟，课堂上等不了。

产品设计上把「实时生成」放在备课环节，课堂上走「秒级调用」。生成过的模型自动入库，系统越用越快。

### 3. 单文件交付

构建产物是**一个 HTML 文件**，双击就能开，不联网、不装环境。

老师最怕的就是「上课前发现打不开」。单文件把这个风险降到最低，也方便微信直接发给同事和家长。

- [x] 触摸 / 投屏适配，WebGL 不可用时友好降级

### 已知限制

| 限制 | 说明 |
|---|---|
| 只有 1 个场景 | 只认「曹冲称象」 |
| 3D 模型是内置占位资产 | 程序化生成的低模，不是 AI 出的 |
| 意图识别是关键词匹配 | 还没接 LLM |
| 没有账号、没有后台 | 纯前端单文件 |

## 七、路线图

### V0.2 · 让它像个产品（下一步）

- 接入真实 AI 链路：即梦 Seedream 出图 → Tripo 转 GLB → 自动归一化入库
- 生成结果缓存到浏览器本地，第二次调用秒开
- 再做 2 个场景，验证模板抽象是否成立
  - **物理 · 杠杆原理**（力臂、平衡）
  - **科学 · 沉浮子 / 密度**（复用浮力内核）

### V0.3 · 给老师和家长试用

- 场景列表页，不用输入也能挑
- 每个场景配一页「教学建议」（怎么讲、问什么问题）
- 部署到线上，一个链接分享
- **目标：找 10 位老师 + 10 位家长真实试用，收集反馈**

### V0.4 · 沉淀

- LLM 意图解析，支持自然表达
- 老师端：收藏、历史、自定义参数（改大象体重、改船大小）
- 场景模板 SDK，让别人也能贡献场景

## 八、怎么判断这个产品成不成

不看下载量，看这三个：

| 指标 | 及格线 | 说明 |
|---|---|---|
| **真实课堂使用率** | 试用老师中 ≥ 3 人主动用第二次 | 用一次是给面子，用第二次才是有用 |
| **家长自发分享** | ≥ 5 位家长转发给其他家长 | 教育产品最真实的信号 |
| **场景开发效率** | 新增 1 个场景 ≤ 3 人天 | 决定这门生意能不能做大 |

第三条是给自己的：**如果做第 4 个场景还是要 6 人天，说明模板抽象错了，得回头重构，而不是继续堆场景。**

## 九、商业化（想清楚再做）

现在**不做商业化**，先把产品和口碑做出来。

可能的方向，按优先级：

1. **面向机构 / 学校的定制场景开发** — 现金流最快，也是当前有客户线索的方向
2. **免费场景库 + 付费的「自定义生成」额度** — 面向个人老师
3. **场景模板授权** — 给已有教育产品做能力嵌入

不碰的：卖硬件、做大而全的教学平台、跟教材版本深度绑定。这些都不是一个人能扛的。

## 十、附录：技术栈

| | |
|---|---|
| 3D 渲染 | Three.js |
| 构建 | esbuild（单文件内联） |
| 语音输入 | Web Speech API |
| 图片生成 | 即梦 Seedream（火山方舟 API） |
| 3D 生成 | Tripo OpenAPI（图生模型 → GLB） |
| 部署 | 静态托管即可 |

成本参考（2026-08 查证）：单个可用 3D 素材约 7 元；200 个知识点建库约 1,400 元。**API 不是成本瓶颈，场景模板开发才是。**
