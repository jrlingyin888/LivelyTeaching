# 小象课堂 LivelyTeaching · 产品文档

> 版本 V0.2 · 2026-08 · 独立开发者项目
>
> **第一期是自用版**：先给自家一年级孩子用，看效果，再给几位朋友试。
> 确定有用，才谈下一期。所有范围决策都以这个前提为准。

---

## 一、一句话定位

**老师在课堂上说一句话，屏幕上就出现一个能动手操作的 3D 实验。**

不是播动画，不是看视频——学生可以拖、可以点、可以改，物理是真算出来的。

---

## 二、为什么做这个

课堂上讲抽象概念时，老师手上只有三种东西：一张挂图、一段视频、一套实物教具。

| | 问题 |
|---|---|
| 挂图 / PPT | 静态，学生看不见过程 |
| 视频 | 只能看，不能动手，讲到哪停不下来 |
| 实物教具 | 贵、占地方、很多实验根本做不了（称大象、看细胞、模拟日食） |

而已有的 3D 课件产品，几乎都是**做好的固定资源包**——老师想讲的知识点如果不在库里，就没有。

**小象课堂的切入点：让课件是「生成」出来的，而不是「买」来的。**

---

## 三、目标用户

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 一线老师（首要） | 课堂讲解、公开课 | 上课前 1 分钟能拿到、投屏就能用、不出错 |
| 家长 | 在家陪孩子讲题 | 手机 / 平板打开就能玩，孩子看得懂 |
| 教研组 / 机构 | 备课资源建设 | 能积累、能复用、能分享 |

**第一期只服务一个人：自家的一年级孩子。**

这不是把野心缩小了，是把验证顺序摆正了——如果一年级孩子对这种形式根本不买账，
后面的生成管线、质检流水线做得再漂亮也没用。先撞这个问题，再谈规模化。

一年级这个约束比"小学"具体得多，而且直接否掉了原来的界面：

| 原来的做法 | 为什么对一年级无效 |
|---|---|
| 「当前吃水深度 0.487 m」 | 不认识那几个字，没学过小数，也没学过单位 |
| 文字 toast 提示 | 识字量覆盖不了，看不完就消失了 |
| 一排 5 个按钮自由探索 | 一年级要的是引导，不是探索 |
| 12 次点击才走完一课 | 注意力撑不到

## 四、产品是什么样的

### 使用流程（第一期）

```
打开一个 HTML 文件
   ↓
首页三张图卡片，孩子点一张（不打字 —— 一年级打不了）
   ↓
装配 3D 舞台，直接进第一步
   ↓
每一步：听一句话 → 猜一猜 → 动手 → 看结果
   ↓
结论卡：再玩一次 / 换一个
```

**原来设计的「说一句话生成课件」这条路没有取消，只是排在后面。**
第一期要先知道孩子买不买账；生成能力再强，形式不对也没用。
中长期怎么走见第七节。

### 已实现的三课

**认识立体图形**（一年级数学）——长方体 / 正方体 / 圆柱 / 球。

3D 在这里有不可替代的价值：一年级最难的一点是**同一个物体从不同角度看形状不一样**。
「圆柱从上面看是什么形状？」先让孩子猜，再把镜头飞到正上方揭晓。
滚坡按 `a = g·sinθ/(1 + I/mr²)` 真算。球和圆柱只差 3%，肉眼看不出，
所以教学落点放在「能滚 / 不能滚」——**不拿看不见的差别当结论**。

**谁轻谁重**（一年级科学）——天平。倾角按真实等臂天平的平衡方程 `tanθ = (mL−mR)·L/(M·d)` 算。

第二步专门用来撞前概念：**大气球 vs 小石头**，多数孩子会猜大的重，天平给出相反的答案。
第三步让孩子一块块加小方块量出气球 2 块、苹果 3 块、石头 5 块，加多了天平往另一边倒
——试错过程是保留的。第四步让孩子把这三个从重到轻排好：它们的**视觉大小顺序和轻重
顺序完全相反**，靠眼睛一定排错，只能照方块数排。这一步是「统一单位」的雏形，也是
往后曹冲称象里「等量代换」的底子，顺带埋下密度的种子（石头最小却最重）。

**曹冲称象**（演示用）——保留数值面板，面向老师演示和高年级。浮力真算 `d = m/(ρ·A)`。

## 五、核心设计决策

### 1. 场景模板化，不是「AI 现场生成一切」

> **修正（V0.2）**：原来这里写的是"AI 生不出交互逻辑"。这个说法太粗了。
> 交互逻辑其实是三层，可生成性差得很远：
>
> | 层 | 例子 | 判断 |
> |---|---|---|
> | 数理内核 | `d = m/(ρA)`、力矩平衡、滚动加速度 | 能生成，但**不该每次生成**——中小学理科底层内核也就几十个，复用率极高 |
> | 场景装配 | 几个物体、多大、怎么摆、镜头在哪 | 能生成，参数化，容易验 |
> | **教学编排** | 分几步、第几步停下来提问、结论怎么给 | **最能生成，也最该生成**，因为它有明确的评价标准 |
>
> 目前手写的那些毛病（该不该等重、要不要先让孩子猜、面板口径矛不矛盾）全部落在第三层，
> 没有一条是"公式算错了"。所以垮的是教学编排层，不是数理内核。

AI 能生成**外观**（大象长什么样），当前版本还没接。

所以架构上分得很清楚：

| 层 | 谁来做 | 说明 |
|---|---|---|
| 外观资产 | AI 生成（即梦 → Tripo） | 大象、船、石块的 3D 模型 |
| 场景装配 | 场景模板（代码） | 水面、比例、光照、镜头 |
| 交互逻辑 | 场景模板（代码） | 浮力、拖拽、数据面板、结论判定 |
| 教学编排 | 模板参数 | 分步演示、提示文案 |

**一个模板覆盖一类知识点，换个外观资产就是另一节课。** 这是这个产品能规模化的关键。

### 2. 素材命中优先，实时生成兜底

AI 实时生成一个 3D 模型要 1.5–3 分钟，课堂上等不了。

产品设计上把「实时生成」放在备课环节，课堂上走「秒级调用」。生成过的模型自动入库，系统越用越快。

### 3. 单文件交付

构建产物是**一个 HTML 文件**，双击就能开，不联网、不装环境。

老师最怕的就是「上课前发现打不开」。单文件把这个风险降到最低，也方便微信直接发给同事和家长。

## 七、路线图

### 第一期（当前）· 自用

给自家一年级孩子用。要拿到的答案只有三个：

1. 他愿不愿意自己玩完一课？
2. 玩完之后，问他「圆柱从上面看是什么形状」，答得出来吗？
3. 第二天他会不会主动再打开？

### 第二期 · 取决于第一期的答案

如果答案是肯定的：

- 按一年级课标补知识点（先补数学「认识图形」和科学「我们周围的物体」两条线）
- **写完第三个场景之后**，把重复的教学编排抽成声明式描述——不预先设计
- 给几位朋友的孩子试，看陌生孩子能不能不用大人讲就玩下去

如果答案是否定的，先搞清楚卡在哪，再决定是改形式还是改学段。

### 更远 · 生成式教学引擎

这是想清楚了但**现在不做**的方向，记在这里防止走岔。

痛点很明确：不可能每个知识点都靠开发者手工发现教学问题。
但结论不是"让 AI 生成一切"，而是：

**1. AI 输出的应该是受约束的声明式描述（DSL），不是 Three.js 代码。**
生成代码不可测、不可审、出错没法降级；生成 DSL 可以拿 schema 卡，可以无头跑一遍自动断言。

**2. 质检里真正的杠杆不在生成侧，在检查侧，而且大部分不需要模型。**
把手工挑出的教学问题逐条抽象成规则后会发现，八成是确定性的：

| 问题 | 规则 | 怎么检测 |
|---|---|---|
| 结果被硬凑成必然成功 | 试错类实验必须存在失败态 | 枚举操作序列，若所有路径必然成功 → 违规 |
| 面板两个数互相矛盾 | 面板任意两数值必须同时自洽 | 每个状态快照跑数值断言 |
| 进度条语义是错的 | 进度指示必须单调且语义单一 | 采样查单调性 |
| 步骤不能回退 | 每步必须有逆操作 | 查 DSL 里 step 有没有 inverse |
| 没有预测环节 | 每课至少一个预测点 | 查有没有 `type: predict` 的 step |

真正需要品味的（这个提问对这个学段合不合适、类比恰不恰当）才交给 LLM critic。
**质量要尽量从"模型能力问题"变成"工程问题"。**

`npm run check` 就是这一层的第一版，已经能跑。

**3. 内核库要能自生长。**
一个学科横跨的内核族比想象中多（力学、光线追迹、电路求解、轨道运动、粒子、规则演化），
不可能全靠手写。所以「AI 生成新内核 → 自动质检 → 真实使用验证 → 晋升进库」这个回路
不是锦上添花，是这条路能不能走通的前提。

**4. 分级放行。**
自动过质检的标「实验版」可用，人审过的标「已验证」，而且**等级要让使用者看得见**。

## 八、怎么判断这个产品成不成

第一期只有一个人在用，所以不看任何统计口径，看三件具体的事：

| 看什么 | 及格线 |
|---|---|
| **孩子愿不愿意自己玩完** | 不用大人在旁边催，能独立走完一课 |
| **玩完之后答得出来** | 隔一天问「圆柱从上面看是什么形状」，答得对 |
| **会不会主动再打开** | 一周内主动要求再玩一次 |

朋友试用阶段加一条：**陌生孩子在没有大人讲解的情况下能不能玩下去。**
这一条最能暴露界面和朗读做得够不够。

第三期以后才谈"新增一课要几天"这种效率指标——现在样本太少，量了也没意义。

## 九、商业化（想清楚再做）

现在**不做商业化**，先把产品和口碑做出来。

可能的方向，按优先级：

1. **面向机构 / 学校的定制场景开发** — 现金流最快，也是当前有客户线索的方向
2. **免费场景库 + 付费的「自定义生成」额度** — 面向个人老师
3. **场景模板授权** — 给已有教育产品做能力嵌入

不碰的：卖硬件、做大而全的教学平台、跟教材版本深度绑定。这些都不是一个人能扛的。

## 十、附录：技术栈

| | |
|---|---|
| 3D 渲染 | Three.js |
| 构建 | esbuild（单文件内联） |
| 语音输入 | Web Speech API |
| 图片生成 | 即梦 Seedream（火山方舟 API） |
| 3D 生成 | Tripo OpenAPI（图生模型 → GLB） |
| 部署 | 静态托管即可 |

成本参考（2026-08 查证）：单个可用 3D 素材约 7 元；200 个知识点建库约 1,400 元。**API 不是成本瓶颈，场景模板开发才是。**
