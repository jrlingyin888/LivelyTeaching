不是播动画，不是看视频——孩子可以拖、可以点、可以猜错重来，**物理是真算的**。

当前版本面向**一年级**：不识几个字也能自己玩完一课。所有关键提示都会念出来，界面上没有小数、没有单位、没有看不懂的仪表盘。

构建产物是**一个 HTML 文件**：双击就能开，不联网、不装环境。

## 已实现的四课

### 1. 认识立体图形 · 一年级数学

长方体 / 正方体 / 圆柱 / 球。五步：认一认 → 看一看 → 滚一滚 → 堆一堆 → 分一分。

3D 在这里有不可替代的价值：一年级最难的一点是**同一个物体从不同角度看形状不一样**。「圆柱从上面看是什么形状？」——先让孩子猜，再把镜头飞到正上方揭晓。

滚坡是真算的：

```
a = g·sinθ / (1 + I/mr²)      球 2/5 · 圆柱 1/2 · 方块不滚
```

球和圆柱的快慢只差 3%，肉眼看不出，所以教学落点放在「能滚 / 不能滚」，**不拿看不见的差别当结论**。

### 2. 谁轻谁重 · 一年级科学

天平。四步：猜一猜 → 大的一定重吗 → 用方块量 → **排一排**。

第二步是专门用来撞前概念的：**大气球 vs 小石头**，多数孩子会猜大的重。天平给出相反的答案。

倾角按真实等臂天平的平衡方程算：

```
tanθ = (mL − mR)·L / (M·d)
```

第三步让孩子一块一块加小方块（气球 2 块 · 苹果 3 块 · 石头 5 块），
加多了天平会往另一边倒——**试错过程是保留的**。

第四步是真的排序：孩子点着把三个物体从重到轻摆好。这三个的**视觉大小顺序和轻重顺序
完全相反**（气球最大最轻、石头最小最重），靠眼睛一定排错，只能照着刚量出来的方块数排——
这就是"用同一样东西去量"这件事的价值。点错不惩罚，只提示"方块多的那个更重"。

### 3. 曹冲称象 · 演示用

面向老师演示和高年级，保留了数值面板。浮力真算：`d = m / (ρ·A)`。

### 4. 四季是怎么来的 · 小学科学（玩具模式）

**没有脚本，没有旁白，没有弹窗。底下一根滑块，拖它。**

拖到哪一天，世界就长成那一天的样子：太阳升高降低、影子伸长缩短、
白天那条黄杠变长变短、地球走到轨道的另一边。想回去，拖回去就行。

| | 夏至 | 冬至 |
|---|---|---|
| 中午太阳高 | 73° | **27°** |
| 影子长 | 0.3 个杆 | **2.0 个杆** |
| 白天 | 14.8 小时 | **9.2 小时** |
| 离太阳 | 15203 万公里 | **14716 万公里** |

最后一行是这一课的引爆点：**冬天反而离太阳更近。** 它不是一道被问的题，
是孩子拖着滑块自己撞上去的。

全真算，没有一个数是写死的：

```
太阳赤纬     δ = 23.44° · sin(2π(N−81)/365)
正午太阳高度  h = 90° − |φ − δ|
影子长度     L = 杆高 / tan(h)
昼长         cos H₀ = −tanφ·tanδ,  昼长 = 2H₀/15 小时
日地距离     r = 1.496 · (1 − 0.0167·cos(2π(N−3)/365)) 亿 km
```

一个刻意的建模决定：**轨道按真实偏心率画（e=0.0167），所以看上去几乎是正圆。**
教科书上那种夸张的大椭圆，本身就是「夏天离太阳近」这个误解的来源之一。

#### 为什么从脚本改成玩具

这一课originally是脚本模式的：念旁白、播动画、弹窗提问。量出来是这样：

| | 脚本版 | 玩具版 |
|---|---|---|
| 旁白和等待占比 | **59%** | 0 |
| 孩子多久能动一次 | **40 秒** | 一直在动 |
| 弹窗遮住画面 | **8 次** | 0 |
| 能不能回退 | **不能** | 拖回去就行 |

根因是**时间归脚本还是归孩子**。脚本版里世界是一串动画，所以没法回退——
压根没有「状态」可回。玩具版里世界是「第几天」这个参数的函数，
滑块就是那个参数。

好在物理本来就是参数化的。之前是把一个能自由转的地球仪，做成了一段录像。

## 面向一年级做了什么

| | |
|---|---|
| **朗读** | 关键提示一律念出来（`speechSynthesis`，全平台）。孩子不识字，但听得懂 |
| **不用数字讲事实** | 天平就是倾角，滚坡就是谁先到底，数量用一排图形表示 |
| **一次最多 3 个大按钮** | 该点哪个就亮哪个 |
| **猜错不惩罚** | 只说「再看看」，不打叉。一年级一旦有挫败感就不肯玩了 |
| **节奏不依赖朗读** | 家长关掉朗读、或浏览器没有 TTS 时，仍按字数留出停顿 |

## 课件自检

`npm run check` 跑的是**不需要人看就能判定对错**的规则。每一条都来自一次真实的返工：

- 每节课至少要有一个「先猜再看」的预测点，否则学生只是在看动画
- 每节课必须走得到结论
- 天平的物体质量必须是方块单位的整数倍，否则会量出「五块多一点」
- 关键词不能撞车（撞了会静默匹配错场景）
- 首页卡片需要的字段一个都不能少

人工发现一次，就沉淀成这里的一条，之后不用再靠眼睛盯。

## 教学编排是声明式的

场景切成两半：

```
场景  =  编排（flow · 声明式）  +  内核（build · 手写：建模 + 物理 + 交互循环）
```

编排只有 7 个词，没有表达式语言：

```js
{say: '这是一台天平。哪边沉下去，哪边就更重', hold: 3400}
{ask: '苹果和小积木，你猜哪个重？', as: 'g1', options: [...]}
{act: 'weigh', args: {a: 'apple', b: 'block'}, as: 'heavier1'}
{judge: {expect: 'heavier1', against: 'g1'}, hint: '苹果那边沉下去了'}
```

`expect` 指向一个变量——答案是**算出来的**（`weigh` 真把两个东西放上天平算力矩）；
`correct` 是写死的字面值。自检会提醒一节课里有没有真算的判定。

**交互循环（反复加方块、点着排序）归内核，不进 DSL**，否则 DSL 会长成一门编程语言，
既不好生成也验不了。

步骤条从 `flow` 派生，不用在 meta 里另写一份——两份必然会不同步。

## 用 AI 生成教学编排

因为编排是声明式的，它可以被生成，也可以被机器校验。

```bash
# 1. 组装 prompt（DSL 词汇表 + 这一课内核提供的动作 + 已有场景范例 + 校验规则）
node gen.mjs seasons "四季是怎么形成的？为什么夏天热、冬天冷？给一年级看…"

# 2. 把 prompts/seasons.md 喂给一个干净的模型会话，拿回 JSON

# 3. 过尺子 —— 和手写编排完全同一套规则
node gen.mjs --verify seasons generated/seasons.flow.json

# 4. 装回场景
node gen.mjs --apply seasons generated/seasons.flow.json
```

传输层是可替换的：现在靠人（或子代理）中转，等接了 API 只需在 `gen.mjs` 里加二十行。

**「四季是怎么来的」这一课的编排就是这样生成的**，一次通过全部校验，零修改。
`generated/seasons.handwritten.json` 是同一课的手写版，留着做对照。
